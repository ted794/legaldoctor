# 규제 변화 피드 형식

리걸닥터가 운영자 보유 규제 변화 분류 자료(대회 전 자산)를 받아 28개 사인 번호로 이어 쓰기 위한 형식. 피드 주소·이름·토큰은 배포 서버 `.env`(`LD_FEED_URL`, `LD_FEED_TOKEN`, `LD_FEED_NAME`)로만 받고 저장소에는 남기지 않음. 값이 없으면 기능이 꺼지고 리걸닥터는 그대로 동작함.

## 요청

- `GET {LD_FEED_URL}?since=YYYY-MM-DD&limit=5000`
- `since` 이후(그날 포함)에 나온 항목만 돌려줌. 처음에는 120일 전부터, 그다음부터는 저장된 가장 최근 날짜부터 받음
- `LD_FEED_TOKEN`이 있으면 `Authorization: Bearer <토큰>`을 붙임
- 리걸닥터는 하루 한 번(cron) 받고, 저장한 지 20시간이 지나면 화면을 열 때 뒤에서 한 번 더 받음. 화면을 열 때마다 피드를 부르지 않음

## 응답

```json
{"items": [
  {
    "id": "고유 번호(같은 항목은 같은 값)",
    "date": "2026-11-10",
    "kind": "법령 개정 | 입법예고 | 행정처분 | 판례 | 가이드라인 | 정책",
    "title": "제목",
    "summary": "두세 줄 요약(선택, 400자까지)",
    "source": "출처 기관(선택)",
    "url": "https://원문 링크",
    "laws": [{"law": "개인정보 보호법", "article": "제64조의2"}],
    "tags": ["개인정보"],
    "effective": "2027-01-01",
    "causes": [20],
    "public": true
  }
]}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `id`, `date`, `title`, `url` | 예 | `date`는 `YYYY-MM-DD`, `url`은 http(s) |
| `public` | 예 | **공개 출처 항목만 true.** false인 항목은 리걸닥터가 버림. 구독자 정보, 고객사별 메모, 내부 분석은 넣지 않음 |
| `laws` | 권장 | 정식 법령명. 검진결과표와 케어의 근거 법령과 이 값으로 이어짐 |
| `causes` | 선택 | 28개 사인 번호. 있으면 그대로 쓰고, 없으면 리걸닥터가 `data/feed/cause_map.json`의 법령명·키워드로 추정함 |
| 그 밖 | 선택 | `kind`, `summary`, `source`, `tags`, `effective` |

## 리걸닥터에서 쓰는 곳

| 화면 | 쓰는 방식 |
|---|---|
| 사인 튜토리얼 '최신 동향' | 이 사인 번호로 분류된 최근 항목(최대 8건)을 Liner Search 결과 위에 보여 줌 |
| 검진 결과·검진결과표 | 판정 근거 법령과 `laws`가 겹치는 최근 항목을 "최근 변화"로 표시 |
| 리걸닥터 케어 | 케어 항목의 근거 법령에 걸린 최근 60일 변화를 "규제 변화 알림"으로, 케어를 시작한 뒤 나온 것은 "새로"로 표시 |

## 보관

- `data/feed/feed.json`(저장소 추적 제외)에 최근 120일, 사인마다 최대 60건만 보관
- 이용자 정보와 섞지 않음. 피드 항목은 공개 출처 자료라 개인정보가 없어야 함
